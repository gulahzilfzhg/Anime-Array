# Security policy

## Reporting a vulnerability

**Please do not open a public issue for a security problem.** A public issue on a live site tells an attacker exactly what they need to know, and the platform cannot be fixed until they have already used it.

Report privately instead:

- **Email:** contact@animearray.site — mark the subject `SECURITY`
- **Contact form:** https://animearray.site/contact-us/ — mark it clearly as a security report

Please include as much of the following as you can:

- what the issue is, in plain terms
- the URL or component affected
- the steps needed to reproduce it
- the impact you believe it has
- anything you have already tried

You do not need to be a security researcher, and you do not need a proof of concept. A clear description of a problem you noticed is worth having.

---

## What to expect

| Stage | What happens |
|---|---|
| Acknowledgement | Within 72 hours of the report being received |
| Triage | Within 7 days: confirmed, needs more information, or not a vulnerability |
| Fix | Prioritised by impact. Critical issues are worked on immediately |
| Disclosure | Coordinated with you. You are told when the fix is live and credited if you want to be |

There is no bug bounty, and it would be dishonest to imply otherwise. What there is: reports are read by a person, genuine reports are acknowledged, and credit is offered.

## Responsible disclosure

Anime Array asks for the following, and it is a request rather than a legal condition:

- **Do not access data you did not already have legitimate access to.** Do not attempt to reach other users' conversations, saved history or account details.
- **Do not degrade the service for others.** No denial-of-service testing, no sustained automated load, no exhausting rate limits.
- **Do not exfiltrate, modify or destroy data.** Prove the issue and stop there.
- **Give reasonable time to fix** before disclosing publicly. A coordinated disclosure timeline of 90 days from the report is normal; ask for more if you need it and it will be given.
- **Do not social-engineer** team members or contact anyone through support channels to obtain information.

Reports that stay inside these boundaries are handled seriously and without friction.

## Scope

**In scope:**

- The Anime Array platform at animearray.site and its subdomains
- This repository and the site published from it
- Authentication, authorisation, session handling and access control
- Injection, cross-site scripting, server-side request forgery and related classes of flaw
- Any vulnerability that could expose user data, conversations or account details

**Out of scope:**

- Vulnerabilities in third-party services, reported to those services
- Missing security headers with no demonstrated impact
- Self-inflicted issues, such as removing your own client-side protections
- Denial of service
- Findings from automated scanners with no demonstrated impact
- Reports generated by an AI tool that have not been manually verified
- Social engineering of the team
- Physical security

Out-of-scope does not mean ignored. A report that is technically out of scope but describes a real weakness is still read, and still acted on if it matters.

## Security approach

Published so that expectations are clear in both directions.

- **Least privilege.** Administrative and data access is restricted to what each component genuinely needs.
- **HTTPS everywhere,** with redirection away from insecure requests.
- **No credentials in the browser.** Integration secrets stay on the server, which is why integrations are called server-side rather than from the visitor's page.
- **Input treated as untrusted.** Anything a visitor can influence is validated before use, and output is escaped according to where it is going.
- **Requests authenticated and authorised** before they take effect, not merely when an interface is opened.
- **Optional accounts.** Because no account is needed to use any core feature, the platform does not need to collect an email address from someone who just wants a recommendation.
- **Reversible changes.** Every change can be undone in a single step, which shortens the time between a problem being introduced and it being removed.

## About this repository

This repository contains **documentation only**. It does not contain the platform's source code, its server configuration, its deployment layout or its credential configuration, and those are deliberately not published.

That means a vulnerability in this repository is almost certainly a documentation or link problem, and the right place to report an operational issue is the private route above.
